# GABAH — Project Rules

**Status:** Authoritative engineering rules  
**Last Updated:** 2026-09-28

These rules apply to humans and AI coding agents.

## 1. Source of Truth

Before changing code: read PRD.md, read relevant docs under docs/, inspect current implementation, and do not infer a rule when the repository already defines it.

If documentation and code disagree, identify the conflict and reconcile it instead of silently choosing one.

## 2. Current Technology

Active architecture: React 19 + TypeScript + Vite → Node.js/Express REST API → Domain Services → PostgreSQL 17. Docker Compose provides the runtime.

Laravel/PHP is not part of the active architecture.

## 3. Backend Authority

The backend must enforce authentication, authorization/RBAC, division scope, asset numbering, asset ownership, duplicate prevention, loan conflict validation, workflow transitions, audit logging, and persistence.

Never rely on a hidden UI button as the only authorization mechanism.

## 4. Database Authority

PostgreSQL is the authoritative operational persistence layer. Do not introduce a competing browser/local data store. Browser localStorage may only be used for session/token handling where required by authentication.

## 5. Asset Rules

- Official GABAH asset numbers are generated by the server.
- Corporate/Accurate numbers are stored separately as corporate_asset_number.
- IT hardware/software/license assets belong to IT.
- Furniture category INV-F belongs to GA regardless of physical location.
- Serial numbers and corporate/Accurate numbers must not be duplicated.

## 6. Security

Never commit passwords, API keys, bearer tokens or production credentials. Do not weaken server authorization. Do not reintroduce production hardcoded auto-login. Preserve brute-force protection and session controls.

## 7. Change Discipline

Keep changes focused. Preserve working behavior unless intentionally changed. Update documentation when architecture, requirements, business rules or security behavior changes. Run type checking/build and relevant tests. Verify persistence after data-related changes.

## 8. AI Agent Rules

AI agents must inspect the repository before proposing architecture changes, use current documentation as constraints, avoid inventing roles/endpoints/tables/workflows, explicitly identify uncertainty, avoid restoring removed Laravel/PHP concepts, and prefer the smallest safe change.

## 9. Definition of Done

A material change is complete only after applicable UI, API, authorization, validation, persistence, audit, regression, build/type-check and documentation verification.
